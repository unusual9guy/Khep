# Khep Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Phase 1 packing workflow from invoice upload through realtime, barcode-validated packing.

**Architecture:** Use a Next.js 14 React frontend and server/API layer, a stateless Python/FastAPI parser, and Supabase for PostgreSQL, Auth, Realtime, and Storage. Cloudflare R2 stores product images; Render hosts the parser and Vercel hosts the web app.

**Tech Stack:** Next.js 14, React, TypeScript, Supabase, Python, FastAPI, PyMuPDF, ZXing.js, Jest or Vitest, pytest, Playwright, and SQL tests or pgTAP.

**Spec:** `docs/Khep_PRD.md`, `docs/admin-flow-spec.md`, `docs/staff-flow-spec.md`, and the visual references in `docs/*.html`.

## Global Constraints

- Treat `docs/Khep_PRD.md` as the absolute source of truth.
- Phase 1 supports Amazon, Myntra, Flipkart, and Pepperfry.
- Myntra uses upload date as its dispatch-date proxy; other platforms read dispatch dates from PDFs.
- Unknown SKUs are flagged and held out of inserted orders; correction is via invoice re-upload.
- All order status writes go through server APIs for AWB validation, points, audit events, and Realtime broadcasts.
- Do not build inventory, courier APIs, returns/RTO, analytics, multi-warehouse support, customer features, or a native app.

## First Milestone
